# implementation notes

## 설계 원칙

- 상위 폴더는 단순하게 유지
- 내부 로직은 기능별로 분리
- 제약조건은 함수 단위로 추가 가능하게 유지
- `config.yaml`에서 제약을 True/False로 제어
- 지금은 큰 틀만 구현하고, 실제 데이터 수령 후 택트타임과 제약 세부 로직을 고도화

## 지금 반영된 핵심 개념

- 병렬 이기종 설비
- 3단계 공정 시간 합산: setup + cut + finish
- 레이저 / 플라즈마 속도 차이
- 설비별 계열 / 두께 / 정반 길이 제한
- 후공정 베이 우선순위 / 적치량 개념
- 하드 / 소프트 제약 분리
- `reset/step` 기반 의사결정 시점 시뮬레이션
- step 단위 액션: `작업 1개를 설비 1개에 배정`

## 현재 환경 해석

- 지금 환경은 `병렬 이기종 설비 PMSP형 골격`입니다.
- 아직 실제 택트타임 분석 결과, 셋업 룰, 후공정 반입 로직이 완전히 들어간 것은 아닙니다.
- 하지만 RL이나 휴리스틱을 붙일 때 필요한 최소 인터페이스는 갖춰져 있습니다.

## 초보자용 제약 추가 예시

1. `Environment/constraints/` 아래 새 함수 작성
2. 반환 형식은 `ConstraintResult`
3. `registry.py`의 `RULES`에 등록
4. `config.yaml`의 `hard_enabled` 또는 `soft_enabled`에 키 추가

Batch PMSP에서 시퀀싱(투입순서)이 의미를 갖는 조건 정리
작성일: 2026-07-07

1. 냉정한 결론

교수님이 말한 "시퀀싱", 즉 batch 또는 W/O 투입순서가 최적화 변수로 의미를 가지려면
단순 부하평준화만으로는 부족하다.

시퀀싱이 의미를 가지려면 목적함수 또는 제약에 시간축이 들어가야 한다.
대표적으로 아래 목적/제약이 있어야 한다.

1) makespan 최소화
2) 완료시각 기반 지표
   - total completion time
   - tardiness
   - due date violation
   - 후공정 착수일 지연
3) ready time/release time
4) setup/changeover
5) crane/transfer/resource conflict
6) 설비별 시간대별 점유율 또는 idle time

반대로 목적함수가 "설비별 총 강재수량, 총 절단장, 총 베벨수량 평준화"뿐이면
설비 안에서 어떤 batch를 먼저 넣는지는 최종 총량을 바꾸지 않는다.
이 경우 시퀀싱은 결과 설명용 간트차트에는 필요하지만, 최적화 변수로서의 의미는 약하다.


2. 왜 단순 부하평준화에서는 순서 의미가 약한가

예를 들어 한 설비에 batch A, B, C가 이미 할당되어 있다고 하자.

batch A 처리시간 = 20분
batch B 처리시간 = 30분
batch C 처리시간 = 10분

설비별 부하를 "처리시간 합"으로만 보면
A -> B -> C = 60분
C -> A -> B = 60분
B -> C -> A = 60분

즉 순서를 바꿔도 설비 총부하는 같다.

강재수량, 절단장, 베벨수량도 마찬가지다.
어떤 순서로 처리하든 해당 설비에 배정된 총량은 변하지 않는다.

따라서 "부하평준화"만 목적이면 핵심 결정은 아래 두 가지다.

1) 어떤 W/O들을 같은 batch로 묶을지
2) 각 batch 또는 W/O를 어떤 설비에 줄지

순서는 부하평준화 값 자체를 바꾸지 않는다.


3. makespan이 들어오면 왜 순서 또는 batch-machine 결합이 의미를 갖는가

makespan은 전체 작업이 끝나는 마지막 시각이다.

병렬설비에서는 아래 결정이 서로 엮인다.

1) W/O grouping
   - 어떤 W/O 1~3개를 같은 batch로 묶는가
   - 길이(LTH) 합 55,000 이하인가

2) batch processing time
   - 현재 절단 문제에서는 batch 내부 W/O TACT_TIME의 max로 보는 것이 자연스럽다.
   - 즉 batch time = max(W/O TACT_TIME)

3) machine assignment
   - 만들어진 batch를 어느 설비에 배정하는가

4) sequencing
   - 같은 설비 위의 batch들을 어떤 순서로 놓는가

만약 ready time, due date, 후공정 착수일, setup, transfer가 전혀 없고
모든 batch가 time 0에 사용 가능하며 목적이 makespan 하나라면,
같은 설비에 이미 배정된 batch들의 내부 순서는 그 설비의 최종 종료시각을 바꾸지 않는다.

하지만 실제 문제에서는 batch가 아직 확정되지 않았고,
어떤 batch를 어느 설비에 넣는지가 makespan을 크게 바꾼다.
따라서 "순서"라는 표현보다 더 정확히는
"batch 구성 + 설비 배정 + 설비별 batch sequence를 통합해 makespan을 최소화한다"가 맞다.


4. 현재 PMSP 절단 문제에 대한 해석

기존 구조:

Phase 1: Block -> Bay 배정
Phase 2: W/O -> Machine 배정
Phase 3: Machine별 batch grouping/sequence

이 구조는 개발/디버깅용 vertical slice로는 의미가 있다.
하지만 최종 최적화 문제로는 Phase 2와 Phase 3을 분리하면 약하다.

이유:

Phase 2에서 W/O를 먼저 설비에 고정하면
Phase 3은 이미 각 설비에 들어간 W/O 내부에서만 batch를 만들고 순서를 정한다.
그러면 "다른 설비에 넣었으면 더 좋은 batch/makespan이 되었을 가능성"을 잃는다.

최종 구조는 아래가 더 맞다.

Phase 1: Block -> Bay 배정

Phase 2 통합: Bay 내부 Batch PMSP
입력: Phase 1에서 해당 Bay에 배정된 block/W/O
결정:
- W/O를 batch로 묶기
- batch를 machine에 배정하기
- machine별 batch 순서 결정하기
제약:
- batch당 W/O 1~3개
- batch 내 LTH 합 <= 55,000
- W/O는 Phase 1에서 정한 Bay 내부 설비만 사용
목적:
- hard violation 0
- makespan 최소화
- 설비별 부하평준화 보조


5. Phase 1/2/3을 유지할 때 Phase 3 순서의 의미

Phase 1, Phase 2, Phase 3을 그대로 나눈다면,
Phase 3의 의미는 현재 입력에 따라 달라진다.

Case A: Phase 2에서 W/O가 이미 machine별로 고정된 경우

이 경우 Phase 3은 각 machine 안에서 W/O를 batch로 묶는 일이 핵심이다.
setup, release time, due date, transfer 제약이 없다면
같은 machine에 만들어진 batch들의 투입순서는 makespan이나 총부하를 거의 바꾸지 않는다.

예:
Machine PLS21에 batch A=20분, B=30분, C=10분이 이미 고정되어 있으면
A-B-C, C-A-B, B-C-A 모두 최종 종료시각은 60분이다.
따라서 이 조건에서는 "투입순서"보다 "어떤 W/O를 같은 batch로 묶었는가"가 더 중요하다.

Case B: 계열 변경 setup time이 있는 경우

이 경우 투입순서는 중요해진다.
setup time은 앞 batch의 계열과 뒤 batch의 계열 조합에 따라 추가 시간이 생기기 때문이다.

예:
Batch A: NP, 20분
Batch B: FL, 30분
Batch C: NP, 10분

NP -> FL 전환 setup = 8분
FL -> NP 전환 setup = 8분
동일 계열 setup = 0분

순서 1: A(NP) -> C(NP) -> B(FL)
총시간 = 20 + 10 + setup(NP->FL 8) + 30 = 68분

순서 2: A(NP) -> B(FL) -> C(NP)
총시간 = 20 + setup(NP->FL 8) + 30 + setup(FL->NP 8) + 10 = 76분

같은 batch와 같은 machine이라도 순서만 바꿔 총시간이 달라진다.
따라서 계열별 setup time이 들어오면 Phase 3는 batch grouping뿐 아니라
batch sequence까지 최적화해야 한다.

Case C: 계열별 batch compatibility가 있는 경우

한 batch 안에 서로 다른 계열을 섞으면 setup, 품질, 작업자 준비, 설비 조건 문제가 생긴다면
grouping 단계부터 계열을 고려해야 한다.

예:
- NP W/O끼리 batch 구성 우선
- FL W/O끼리 batch 구성 우선
- 서로 다른 계열을 섞는 batch는 금지 또는 penalty
- 같은 계열 batch를 연속 배치해 setup 횟수 최소화

이 경우 최종 Phase 3 결정은 아래처럼 된다.

1) 같은 batch 안에 어떤 W/O를 묶을 것인가
2) batch의 대표 계열은 무엇인가
3) 어떤 machine에 넣을 것인가
4) 같은 machine 안에서 어떤 계열 순서로 처리할 것인가

즉 계열 setup이 들어오면 "그룹핑"과 "순서"가 분리되지 않는다.
좋은 grouping은 setup을 줄이는 sequence를 쉽게 만들고,
나쁜 grouping은 아무리 sequence를 잘 잡아도 setup이 많이 생긴다.


6. 목적함수 우선순위 제안

실무/논문 양쪽을 고려하면 아래처럼 두는 것이 가장 방어 가능하다.

1순위: hard constraint violation = 0
   - batch W/O 개수
   - batch LTH 합
   - Bay/Machine eligibility
   - 추후 광폭, 계열, 선호설비 제약

2순위: makespan 최소화
   - Bay 내부 마지막 batch 완료시각
   - 또는 전체 Bay 중 최대 완료시각

3순위: 부하평준화
   - 설비별 W/O 수
   - 설비별 TACT_TIME 합
   - 설비별 절단장 합
   - 설비별 베벨수량 합

주의:
부하평준화와 makespan은 항상 같은 방향이 아니다.
예를 들어 빠른 설비 또는 유리한 batch 조합에 몰아주면 makespan은 줄 수 있지만
설비별 W/O 수 평준화는 나빠질 수 있다.
따라서 둘을 동시에 넣으려면 사전식 목적함수 또는 weighted multi-objective가 필요하다.


7. 교수님 질문에 대한 답변 문장

"투입순서에 의미를 주려면 단순히 설비별 총 부하평준화만으로는 부족합니다.
설비별 총량만 보면 순서를 바꿔도 값이 변하지 않기 때문입니다.
시퀀싱이 최적화 변수로 의미를 가지려면 makespan, 완료시각, due date, ready time, setup, transfer 같은 시간축 목적/제약이 들어가야 합니다.
따라서 최종 모델은 Phase 2 W/O-설비 배정과 Phase 3 batch/sequence를 분리하기보다,
Bay 내부에서 W/O grouping, batch-to-machine assignment, batch sequencing을 동시에 결정하는 Batch PMSP로 두는 것이 맞습니다."


8. 참고문헌 정리

1) Fowler, J. W. and Mönch, L. (2022)
   A survey of scheduling with parallel batch (p-batch) processing.
   European Journal of Operational Research, 298(1), 1-24.
   DOI: 10.1016/j.ejor.2021.06.012
   핵심 근거:
   parallel batching에서는 grouping decision이 conventional assignment/sequencing decision에 추가된다.
   makespan, flow time, due-date related measures가 주요 성능지표로 다뤄진다.
   URL: https://ideas.repec.org/a/eee/ejores/v298y2022i1p1-24.html

2) Brucker, P., Gladky, A., Hoogeveen, J. A., Kovalyov, M. Y., Potts, C. N., Tautenhahn, T., and van de Velde, S. L. (1998)
   Scheduling a batching machine.
   Journal of Scheduling, 1(1), 31-54.
   DOI: 10.1002/(SICI)1099-1425(199806)1:1<31::AID-JOS4>3.0.CO;2-R
   핵심 근거:
   batching machine은 최대 b개 job을 동시에 처리할 수 있고,
   같은 batch의 job은 동시에 시작/종료하며,
   batch 처리시간은 batch 내부 job 중 가장 긴 처리시간이다.
   URL: https://research.tue.nl/en/publications/scheduling-a-batching-machine/

3) Damodaran, P., Velez-Gallego, M. C., and Maya, J. (2011)
   A GRASP approach for makespan minimization on parallel batch processing machines.
   Journal of Intelligent Manufacturing, 22, 767-777.
   DOI: 10.1007/s10845-009-0272-z
   핵심 근거:
   identical parallel batch processing machines에서 makespan 최소화를 다룬다.
   각 machine은 capacity를 넘지 않는 한 여러 job을 동시에 batch로 처리할 수 있다.
   URL: https://link.springer.com/article/10.1007/s10845-009-0272-z

4) Arroyo, J. E. C. and Leung, J. Y. T. (2017)
   Scheduling unrelated parallel batch processing machines with non-identical job sizes and unequal ready times.
   Computers & Operations Research, 78, 117-128.
   DOI: 10.1016/j.cor.2016.08.015
   핵심 근거:
   arbitrary job sizes, non-zero ready times, unrelated parallel batch machines에서 makespan 최소화를 다룬다.
   machine은 capacity를 넘지 않는 한 여러 job을 batch로 동시에 처리한다.
   URL: https://www.sciencedirect.com/science/article/abs/pii/S030505481630209X

5) Scheduling identical parallel batch processing machines to minimise makespan using genetic algorithms (2009)
   핵심 근거:
   parallel batch processing machine에서 필요한 결정은
   grouping jobs into batches와 scheduling batches on machines라는 두 의사결정이다.
   batch processing time은 batch 내부 가장 긴 job processing time이다.
   URL: https://ideas.repec.org/a/ids/eujine/v3y2009i2p187-206.html

6) Potts, C. N. and Kovalyov, M. Y. (2000)
   Scheduling with batching: A review.
   European Journal of Operational Research, 120(2), 228-249.
   핵심 근거:
   batching scheduling 전반의 review 논문이다.
   현재 문제를 일반 scheduling-with-batching 문헌 안에 위치시킬 때 사용한다.
   URL: https://ideas.repec.org/a/eee/ejores/v120y2000i2p228-249.html

7) Gahm, C., Wahl, S., and Tuma, A. (2022)
   Scheduling parallel serial-batch processing machines with incompatible job families, sequence-dependent setup times and arbitrary sizes.
   International Journal of Production Research, 60(17), 5131-5154.
   DOI: 10.1080/00207543.2021.1951446
   핵심 근거:
   job family compatibility, sequence-dependent setup time, arbitrary job size가 함께 있는 parallel serial-batch machine 문제다.
   계열이 바뀔 때 setup time이 있으면 batch grouping과 machine sequence가 함께 중요해진다는 근거로 사용한다.
   URL: https://ideas.repec.org/a/taf/tprsxx/v60y2022i17p5131-5154.html

8) Tran, T. T., Araujo, A., and Beck, J. C. (2016)
   Decomposition Methods for the Parallel Machine Scheduling Problem with Setups.
   INFORMS Journal on Computing, 28(1), 83-95.
   DOI: 10.1287/ijoc.2015.0666
   핵심 근거:
   unrelated parallel machine scheduling에서 sequence- and machine-dependent setup time과 makespan 최소화를 다룬다.
   setup이 있으면 machine assignment와 machine별 sequence가 분리되지 않는다는 근거로 사용한다.
   URL: https://pubsonline.informs.org/doi/10.1287/ijoc.2015.0666


9. 현재 개발 방향 반영

즉시 코드에서 할 일:

1) Phase 1은 유지한다.
   - Block -> Bay
   - Bay별 설비 수를 고려한 부하평준화

2) 기존 Phase 2/3는 최종 모델에서 통합한다.
   - 이름 후보: Phase 2 Batch PMSP
   - 기존 Phase 2/3 코드는 독립 실험용 vertical slice로 남겨둘 수 있지만,
     최종 발표/논문 구조에서는 "분리 모델"이 아니라 "통합 전 단계"로 설명해야 한다.

3) 통합 Phase 2의 action 후보는 아래처럼 설계한다.
   - open/construct batch
   - add W/O to batch
   - assign batch to machine
   - append batch to machine sequence

4) 처음부터 너무 복잡하게 하지 말고, baseline은 아래로 시작한다.
   - 휴리스틱: best-fit batch 구성 + earliest completion machine 배정
   - RL/self-labeling: 휴리스틱 후보 + agent sampling 후보 중 score가 가장 좋은 complete schedule을 teacher로 사용

5) score는 최소한 아래 tuple로 시작한다.
   - hard_violation_count
   - makespan
   - machine_tact_gap
   - machine_wo_count_gap
   - machine_cut_gap


10. 절단협의자료.pdf 반영: 계열/설비 선호와 통합 Phase 2 action

절단협의자료.pdf 2페이지에는 설비별 작업 가능 계열 및 크기 제약이 있다.
표의 의미는 아래와 같다.

1: Main
2: 선호
3: 비선호
4: 과부하 시

현재 플라즈마 설비 기준:
- Bay 22/23/24의 PLS21~24, PLS31~33, PLS41~44는 NP=1, FN=2, FL=3, NC=4다.
- Bay 25의 PLS51~52는 FN=3, FL=1이다.
- Bay 6의 PLP01~02도 FN=3, FL=1이다.

현재 베이-계열 제약:
- Bay 22/23/24: NP=1, FN=2, FL=3
- Bay 25/TRANS: FN=3, FL=1

레이저 투자 기준 베이-계열 제약 안:
- Bay 22/24: NP=1
- Bay 23: NP=1, NC=2
- Bay 25/TRANS: FN=2, FL=1

따라서 Phase 2/3를 통합할 경우 action은 아래처럼 정의하는 것이 맞다.

action = (feasible_batch_candidate, target_machine_next_slot)

여기서 feasible_batch_candidate는 W/O 1~3개 묶음이다.
하지만 모든 조합을 action으로 펼치지 않고, candidate generator가 제한된 후보만 만든다.

candidate generator 우선순위:
1) 같은 계열 W/O끼리 3개 batch 우선
2) 길이(LTH) 합 55,000 이하
3) 계열별 Main/선호 설비에 넣기 좋은 batch 우선
4) due date 또는 후공정 착수일이 비슷한 W/O 우선
5) 3개 batch가 불가능하거나 나쁜 경우에만 2개/1개 batch 후보 생성

edge score에는 아래 항목을 넣어야 한다.

1) hard feasibility
   - W/O 수 <= 3
   - LTH 합 <= 55,000
   - Phase 1 Bay 내부 설비인지
   - 계열별 작업 가능/선호 설비인지

2) preference cost
   - Main: 0
   - 선호: 작은 penalty
   - 비선호: 큰 penalty
   - 과부하 시: 기본 금지 또는 매우 큰 penalty

3) setup/changeover cost
   - 같은 계열 연속이면 0
   - 계열 변경이면 setup time 또는 setup penalty

4) projected time
   - projected_finish_time = machine_available_time + setup_time + max(batch TACT_TIME)
   - projected_makespan

5) load balancing
   - 설비별 TACT_TIME gap
   - 설비별 W/O 수 gap
   - 설비별 절단장 gap
   - 설비별 베벨수량 gap

교수님 질문에 대한 핵심 답변:
단순히 W/O를 설비에 배정하고 나중에 grouping만 하는 구조라면 순차성이 약하다.
하지만 절단협의자료의 계열별 Main/선호/비선호 설비 제약과,
추후 setup/changeover time을 포함하면
현재 설비의 마지막 계열과 현재 부하 상태가 다음 batch-machine action의 비용을 바꾼다.
따라서 이 경우에는 통합 Phase 2를 MDP로 정의할 수 있다.

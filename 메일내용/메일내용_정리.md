# 메일내용 정리

정리 대상 파일은 `절단 문의사항 정리_05.14.docx`, `절단03~04_NP물량_마스킹.xlsx`이다. 메일 기준으로 현업은 2026년 3월~4월 NP 계열 물량에 대해 먼저 알고리즘 결과를 확인하려고 하며, 다른 계열 물량은 추후 공유 예정이다.

---

## 1. Word Q&A 핵심 정리

`절단 문의사항 정리_05.14.docx`의 답변은 두 종류로 구분된다.

| 색상 | 의미 | 처리 |
|---|---|---|
| 갈색 | 거제 방문 시 답변 | 기존 기준으로 참고 |
| 하늘색 | 새롭게 정리된 답변 | 우선 반영 |

### 1.1 바로 반영할 확정 규칙

| 항목 | 답변 요약 | 모델 반영 방향 |
|---|---|---|
| 작업 순서 | `WK_SEQ` 컬럼 제외 | 작업 순서는 쓰지 않고 착수일, BAY, 장비 배정을 결정 |
| 실적 시각 이상치 | 종료시각이 시작시각보다 빠른 데이터는 삭제 | 음수 duration row 삭제 |
| 송선단계 | 후공정 소요일을 기준으로 착수일 결정 | 후공정일/소요일을 일정 제약으로 사용 |
| `STL_REQ_DT` 결측 | 모두 삭제 | 신규 데이터에는 해당 컬럼이 없으므로 대응 컬럼 확인 필요 |
| 계열 | NP 계열 알고리즘 초안 먼저 개발 | 1차 학습/실험은 NP 중심 |
| 계획 착수일 | 새로운 계획 착수일 컬럼 참고 | 신규 데이터의 `GYEL_ACT_STDT` 우선 사용 |
| 설비-계열 우선순위 | penalty가 아님 | 1, 2순위 우선 배정, 불가능할 때만 3, 4순위 허용 |
| BAY-계열 우선순위 | penalty가 아님 | 우선순위 기반 candidate 필터링으로 처리 |
| 광폭 | 고려하지 않음 | 1차 모델 제외 |
| NCG | 고려하지 않음 | 1차 모델 제외 |
| 한 BAY 내 복수 설비 | 각 설비가 독립적으로 운행 | 설비별 독립 machine으로 모델링 |
| 정반 라인 길이 | 각 설비에 W/O 3개까지 가능, 3개 길이 합 55000 이하 | 설비별 동시 작업 수와 길이 합 제약 반영 |
| 블록셋 | 동일 프로젝트, 동일 블록명 | 같은 프로젝트+블록은 동일 BAY 배정, 설비까지 동일할 필요는 없음 |
| 크레인 | 현재 고려하지 않음 | 1차 모델 제외 |
| 후공정 일정 | 제약으로 설정 | hard constraint 또는 강한 제약으로 반영 |
| 목적함수 | 결과를 보면서 조정 | 초기 weight는 실험 후 튜닝 |
| 설비 범위 | 먼저 22, 23 BAY 설비만 고려 | 1차 모델 범위는 22/23 BAY |

### 1.2 처리시간 관련 핵심 이슈

| 항목 | 답변 요약 | 반영 방향 |
|---|---|---|
| `TACT_TIME`과 실적 시간 차이 | 부재 수량, 두께, 절단 길이와 택트타임, 실적 시각 차이 간 상관관계 분석 요청 | `TACT_TIME`과 실제 elapsed time을 분리해서 분석 |
| 택트타임 세분화 | 네스팅/절단/선별 분해 값은 모수가 적고 부정확 | 1차에서는 세분화하지 않고 총 처리시간 기준으로 사용 |
| 자재 정보 | 두께, 폭 추가 전달 예정이나 광폭은 제외 | 신규 데이터의 `THK`는 사용, 폭은 1차 제외 |

### 1.3 추후 확인 또는 보류 항목

| 항목 | 현재 답변 | 보류 사유 |
|---|---|---|
| 후공정 4단계 매핑 | 필요시 추후 고려 | 현재는 후공정 소요일 기준으로 진행 |
| 전체 설비-계열 우선순위표 | 추후 전달 | NCG/LSR 등 전체 기준 미확정 |
| 다른 계열 값 | 추후 전달 | 현재는 NP 초안 우선 |
| 설비 세부 구조 | 22, 23 BAY부터 고려하고 추후 회의 정리 | 전체 공장 DES로 확장 전 단계 |
| 판넬 전용 BAY | 25, trans BAY, soft 제약 | 현재 데이터는 22/23 BAY라 직접 적용 대상 아님 |
| 레이저 20T 제약 | 레이저는 20T 이하, 플라즈마는 20T 초과 우선 | 현재 데이터 장비는 PLS 계열 중심이라 추후 확장 시 반영 |

## 4. 처리시간 분석 메모

`TACT_TIME`은 실제 착수-종료 시간 차이와 완전히 일치하지 않는다. 현업 답변에서도 부재 수량, 두께, 절단 길이와의 상관관계 분석을 요청했다.

| 비교 항목 | `TACT_TIME`과의 상관계수 |
|---|---:|
| 실제 elapsed time | 0.3688 |
| `CUT_LTH` | 0.8537 |
| `PTLST_QTY` | 0.6264 |
| `LTH` | 0.5149 |
| `MARK_LTH` | 0.4385 |
| `BVL_LTH` | 0.1119 |
| `THK` | -0.0827 |

해석은 다음과 같다.

- `TACT_TIME`은 절단 길이(`CUT_LTH`)와 가장 강하게 연결된다.
- 실제 elapsed time과 `TACT_TIME`의 상관은 낮은 편이라, 실적 시간에는 대기, 준비, 중단, 병렬 작업, 기록 방식 차이가 섞였을 가능성이 있다.
- 1차 처리시간 모델은 `TACT_TIME`을 기본값으로 쓰고, 실제 elapsed time은 검증/비교용으로 분리하는 편이 안전하다.
